# crates/targets/spyre — `scratchy-target-spyre`

## OVERVIEW
IBM Spyre (KTIR) backend: SubtileIR → KTIR → SuperDSC lowering, dxp bake, and card/emulator runners. Earned its file: ~37k LOC src, 25 test binaries, 4 workspace crates, and the macro's spyre path resolves here.

## STRUCTURE
```
spyre/
├── src/          # lowering + bake + runners (see WHERE TO LOOK)
│   └── ir/       # island::* = stage data types, bridge::x_y = translations (subtile_tape→tile_op→tiled_op→sdsc_op)
├── bundle/       # scratchy-spyre-bundle: baked-artifact type family + inventory registry (feature-free leaf)
├── builder/      # scratchy-builder-spyre: EMPTY placeholder, kept so old feature wiring resolves
├── flex-rs/      # Rust port of flex runtime + senlib FFI (own AGENTS.md)
├── kernels/      # Triton .py kernels; include_str!'d by crates/triton/splice/src/lib.rs
├── ktir/         # vendored KTIR crates (ktir-core, -emulator, -optimizer, -superdsc) — separate subtree
├── tests/        # integration tests (inline #[cfg(test)] wouldn't run at default features)
└── examples/     # 3 need spyre-hw (bundle_run_dev, hazard_concurrency, shared_host_pool_probe)
```

## CONVENTIONS
- Features are additive siblings: hidden `spyre` (target-neutral), `spyre-hw` (card; the ONLY cfg that gates the SDK, pulls flex-rs), `spyre-emu` (emulator; NOT a fallback for hw). No per-revision feature.
- `bundle_code`, `ktir`, `scratchy-triton-splice`, `ktir-superdsc` are unconditional: macro tokens (`::scratchy_target_spyre::bundle_code::…`) land under bare `spyre`.
- Bundle crate: one `Cow<'a>` type family shared by emitter, macro consts and runtime — no conversion structs. Quantities are newtypes (`SiblingFp`, `SweptCols`, `RungSeqs`, `RowIdx`); no `From<u32>`.
- `RerollMeta` is destructured exhaustively in codegen — adding a field is a build error until baked.
- Unmapped op kinds are `Err` naming the node, enumerated, never `_`.
- `⛔`/`⭐` doc comments record paid-for invariants; read before changing the code they sit on.
- Test names are full-sentence laws; `zz_` prefix groups attention/address-law pins.

## ANTI-PATTERNS
- Pulling flex-rs into a cuda/metal/emit-only build. A new card-only example without `required-features = ["spyre-hw"]` in Cargo.toml.
- A `bridge::x_y` module that both translates and transforms. `subtile_tape_tile_op` is pure syntax: no row-count branches, no decomposition. Composite ops (RmsNorm, RoPE, AttnDecode) decompose only in `tiled_op_sdsc_op`/the emitter.
- The emitter reading the `#[forward]` shell. Printing KTIR text instead of constructing `IRFunction`s. Naming tensors by `format!("t{id}")`.
- Re-adding a `lower_ktir_to_superdsc` module here (name collision with the real lowering in ktir-superdsc).
- Build-dependency from `builder/` on `scratchy-models` (compiled every model twice, ~13 GB).
- KV budget derived from anything but the card's own capacity (`runtime.rs`). Device-computed gather strides: page slots come from the HOST page map.
- dxp cache serving or keeping another compiler's program; a truncated entry is a MISS.
- `src/pc.rs` is TEMPORARY instrumentation — strip with its call sites, don't build on it.

## COMMANDS
```bash
cargo test -p scratchy-target-spyre                                    # cardless default tests
SCRATCHY_PLAN_ONLY_BAKE=1 cargo test -p scratchy-target-spyre --test superdsc_time_tile  # also head_norm_sandwich, lm_head_tail_extraction
cargo clippy -p scratchy-target-spyre --features spyre-emu --all-targets -- -D warnings  # CI linux-spyre-triton
cargo test   -p scratchy-target-spyre --features spyre-emu --lib --tests                 # CI (not bare: examples need a card)
cargo run -p scratchy-target-spyre --example bundle_run_dev --features spyre-hw          # card host only
```
- Set `SCRATCHY_PLAN_ONLY_BAKE` from the caller, never in-test (`set_var` is unsafe in edition 2024, races bake threads). Without it, bake refuses on hosts with no dxp.
- `SCRATCHY_SUPERDSC_DBG` = numeric-bisection golden dump (path or `=1` → temp dir); read via `bundle::dbg_golden_dir`.
- Clippy `--all-targets` at default features is rc 101 on main (18 pre-existing test-target lints); not your regression.
